## 0. Design rules (from user research; each is testable)
1. **Never require a pinch, grip, thumb-to-finger touch, an isolated pointing finger held for long periods, or sustained wrist flexion/extension.** Pinch loads the thumb base joint and the median nerve; it is among the most painful gestures for this group. The pointer landmark is a setting: index fingertip (hand landmark 8, default), index knuckle (5) for a relaxed open hand, or middle-finger knuckle (9) for a loose fist. Downstream code is landmark-agnostic. Coaching text says "Let your other fingers curl loosely; you don't need to point."
2. **Rested, small movements.** Hand mode tracks a hand whose **wrist rests on the desk, a book or a rolled towel**; never a hovering hand (that holds the wrist in extension) and never a forearm propped vertically and steered by the wrist. A small calibrated "active box" in the camera frame maps to the whole canvas (gain derived from calibration; 3× is the uncalibrated default; slider 2–10×). Never require mid-air arm drawing.
3. **Filter before gain.** Smoothing runs on raw landmark pixels; gain is applied after.
4. **Every action is reachable three ways** — a tile (dwell or click), a voice phrase, and a visible typed-command box using the same grammar — and the nine core actions in the §3 key map also have a key. Build one action table (`src/actions.ts`: id, label, voice phrases, typed form, key or null, destructive?) and generate the tiles, key handling, grammar and typed box from it. Nothing is voice-only (Parkinson's dysarthria is common; one published study measured ~36 % word error for off-the-shelf speech recognition on it) and nothing is dwell-only (CP users often can't hold still). Each input method can be switched off independently (WCAG 2.5.4).
5. **No time limits, no auto-advance, no drag required for UI** (WCAG 2.2.1, 2.5.1, 2.5.7). Freehand drawing is the only essential drag. Reminders never block; they are dismissed by the user's next action, and that action still executes.
6. **Big targets, high contrast, scalable, screen-reader-correct.** Tiles are real `<button>`s with visible text labels, ≥ 64×64 px, visible 3:1 focus ring, logical tab order, fully keyboard-operable; toggle tiles (Pen, Latch, Mic, Head mode, Simulate tremor) expose `aria-pressed`. Sliders are native `<input type="range">` with a visible `<label>` and `aria-valuetext` ("Steadiness 70 of 100"). The `<canvas>` has `role="img"` and an `aria-label` updated on pen-up ("Drawing canvas, page Notes 1, 14 strokes"); the dwell ring is `aria-hidden`. Text ≥ 18 px, contrast ≥ 4.5:1 (UI ≥ 3:1); usable at 200 % browser zoom. The toolbar is a wrapping grid; when it would not fit, actions are grouped behind category tiles (Colours, Tools, View, Pages) that open a sub-panel. The toolbar is never a scroll container (dwell and switch users cannot scroll). Status text ("Tracking lost: too dark", "Heard: make it blue", "Pen down") lives in an `aria-live` region: `role="status"` for routine updates, `role="alert"` for tracking loss. Destructive confirms are a modal `role="alertdialog"` (`aria-labelledby`/`aria-describedby`, focus moved to Cancel on open and restored on close, background inert). Enter/Space activate the focused button, so a stray press cancels. Confirming requires the ✓ Confirm tile (dwell/click), typed "yes", voice "yes" with exact match only (no fuzzy matching while any dialog is open), or Tab to Confirm then Enter. Esc always cancels. Respect `prefers-reduced-motion` (stepped dwell indicator; no tremor-simulation animation unless explicitly enabled).
7. **Undo is one action, never timed.** A persistent status-bar "Undo: <last action>" affordance, the Undo tile, `Backspace` or `Z`, and voice "undo". Toasts may animate but never carry exclusive functionality.
8. **Ability varies hour to hour** (morning stiffness, Parkinson's on/off, flare days, fatigue). Everything tunable has a slider; voice "steadier" / "looser" moves Steadiness ±10; profiles are user-named (two pre-created, renamable: "Steady day", "Shaky day"; unlimited more) and switch by one voice phrase or one tile.
9. **Privacy, stated truthfully on the first-run screen.** Camera frames never leave the browser. Microphone audio goes to Cartesia (or Google, in the Web Speech fallback) only while the mic is open. A command the local grammar cannot match (its text, never audio, plus your last three actions) and, only when you explicitly ask for AI cleanup, stroke data plus a PNG crop go to our server and on to Anthropic. Nothing else leaves the browser. In Desktop mode the browser also sends pointer positions and shortcut keystrokes to a helper program on this same computer (`127.0.0.1` only); the helper never sends anything off the machine. The "Ask Steady" research index (P3) is built from public web pages scraped with Apify on our server; no user data, audio or drawings ever go to Apify or Elastic.
10. **Fail safe.** If tracking is lost for > 300 ms the pen lifts and freezes; the cursor becomes a hollow "?" ring and the status says why (no hand / too dark / low fps) and what to do. Never scribble. Tracking loss lifts the pen even when Latch is on; on re-acquire the pen stays up until the user's next explicit pen-down (dwell / Space / voice / face). Status: "Tracking back. Pen is up."
11. **Never diagnose.** No preset, label, Help text or readout names a condition or shows a tremor frequency. Presets and Help describe what the hand does ("steady but sore", "shakes when reaching", "shakes at rest", "hard to hold still").

**P0 definition of done:** within 60 s of `npm run dev`, a person at this laptop can see their fingertip cursor, hold still to start drawing, draw a legible word, hold still to stop, press Backspace to undo, and download a PNG, with the Steadiness slider visibly changing the result. Because no human is present, verify P0 with `ReplaySource` (synthesised landmark JSON: a slow word-shaped path with 6 Hz jitter added) and the Playwright fake-camera run, then write the six-item checklist to `NEEDS-HUMAN.md` under "Verify on a real webcam first thing in the morning" and continue to P1.

## 2. Pointer pipeline (Hand mode; Head mode reuses it with face landmark 1, the nose tip)
raw landmark → camera pixels (640×480 space) → **One Euro filter, one instance per axis** (mincutoff 0.6 Hz, beta 0.005, dcutoff 1.0; real timestamps; pixels) → **active-box mapping** to canvas px → **dwell detector reads here** → **lazy-brush dead zone** (radius 12 px, friction 0) → pointer.
- Why: tremor is ~4–12 Hz (essential tremor), 4–6 Hz (Parkinson's rest), 2–5 Hz (intention tremor/CP, overlapping intended movement, which is why the dead zone exists). Intended strokes are ~1–3 Hz.
- **Acceptance targets, measured at the One Euro output in canvas px (before the dead zone), synthetic input at 30 fps, steady state after 1 s (same numbers in §9):** (a) 200 px/s ramp on x with 6 Hz ±5 px jitter on y → RMS y residual ≤ 0.75 px (15 %); (b) 2 Hz ±50 px sinusoid on x → output amplitude ≥ 32.5 px (65 %); (c) ramp lag (time shift minimising x error) ≤ 150 ms. If a target fails at defaults, sweep beta over 0.003–0.01, pick the smallest passing value, record it in DECISIONS.md. **Dead-zone test, separate:** (i) a stationary point carrying (a)'s filtered y jitter, no ramp, through lazyBrush R = 12 → pointer never moves; (ii) a 300 px x-ramp ends exactly 12 px short of the cursor; (iii) during (a)'s ramp the pointer's y RMS is ≤ the One Euro output's y RMS (not zero; a dragged dead zone removes jitter only while the hand is still).
- One **Steadiness** slider 0–100 (default 50 until calibration suggests otherwise) maps piecewise-linearly through the §2 defaults: 0 → (1.2 Hz, 4 px), 50 → (0.6 Hz, 12 px), 100 → (0.3 Hz, 30 px), so the slider's default position is exactly the tested configuration. An Advanced panel exposes raw parameters live.
- **Presets** (tiles + voice; P3): *Sore joints, steady hand* (Steadiness 25, gain 3×); *Shakes when holding still or reaching* (Steadiness 70); *Slow movements, shakes at rest* (Steadiness 45, gain 4×, dwell 1200 ms, **Latch ON** so the pen never lifts on its own; pen-up by Space / voice / face tap; optional ruled guide lines); *Hard to hold still* (Steadiness 60, **Latch ON**, pen toggle by Space / voice / face tap, `dwellRadius` override 60 px replacing the §3 `r_in` formula for tiles, snap-to-target: tiles count as hovered within 40 px of their edge). Profiles store the user's own values.
- **Calibration, two steps, ≤ 10 s:** (1) "Rest your hand and hold still": 3 s, measures rest jitter; (2) "Slowly draw a circle as big as feels easy": 4 s, sets the active box (padded 20 %), derives the gain from it (canvas width ÷ box width, shown on the Gain slider which then edits that value live, range 2–10×; if the circle would need > 10×, coaching asks once for a slightly larger circle, then accepts) and left/right hand, and measures the high-frequency residual during movement (kinetic tremor is worse than rest tremor for most essential-tremor users). Suggested Steadiness = the larger of the two, shown only as a slider position. Coaching text plus a one-line diagram show the supported-wrist posture. Persist calibration, profile and camera in `localStorage`; next launch offers "Use last setup" so a returning user draws within 3 s. After calibration the camera preview collapses to a 120 px thumbnail with a green/amber/red tracking dot; a lighting warning shows if mean luma is low. "Recenter" reruns step 2 in 3 s; "Re-measure" reruns step 1 without changing the box.
- Setting "Auto-switch to Head mode when the hand is lost for 2 s": default OFF.
- **Head mode (P3):** nose tip, gain default 6× (slider 3–10×), neutral set at calibration, "recenter". Break reminder default every 10 min in Head mode and 15 min in Hand mode (non-blocking; can be off; tremor amplitude rises with fatigue).

## 3. Pen state, dwell, key map
- States: `HOVER` (hollow cursor, no ink) ↔ `DRAWING` (filled cursor, coloured border around the canvas). Earcons: two distinct clicks for pen down/up (default on, togglable). Never speak on pen toggles.
- **Pen-down dwell** (evaluated on the pre-lazy-brush point, canvas px): still when all points in the last 250 ms lie within `r_in = max(15 px, lazyRadius/2, 3 × rest-jitter RMS from calibration step 1 measured at the One Euro output)` of their centroid; cancel only beyond `r_out = 2 × r_in`. Default 800 ms (slider 500–1500). Stepped/filling ring feedback. **Arming:** after a pen-down dwell, the pen-up dwell is armed only once the pointer has moved > `r_in` from the pen-down anchor; after a pen-up dwell, the next pen-down dwell is armed only after 600 ms. A hand that simply rests therefore toggles at most once and never leaves ink; dots come from Space, voice/typed "dot", or a deliberate second dwell after moving away and back.
- **Pen-up dwell:** own slider 800–3000 ms, default 1.5 × pen-down (1200 ms at defaults), tighter test: lift only if the point has stayed within `r_in / 2` of where stillness began for the whole dwell (no `r_out` hysteresis). Show the ring so the user can nudge to keep drawing. Slow deliberate drawing must never lift the pen (test: a 40 px/s straight stroke lasting 3 s at defaults never triggers pen-up). On pen-up trim the dwell-period points from the stroke end; on pen-down start at the dwell anchor.
- **Latch** (tile/voice/setting): pen stays down until an explicit key/voice/face pen-up. Ink is recorded only while the pointer is over the canvas; leaving the canvas ends the current stroke, and if the pen is still down a new stroke starts where the pointer re-enters, with no connecting line. **Dot:** if a stroke's bounding box is smaller than `r_in` at pen-up (any method), render a single dot of the current width at the anchor instead of discarding it; voice/typed "dot" places one at the cursor.
- **Rest zones:** a wide margin around the canvas plus the toolbar where dwell never toggles ink; dwelling on a tile activates it. A "Pause tracking" tile stops all pointer input until resumed by key, voice or click.
- **Key map (fixed, shown in Help and on first run; every other key does nothing; remappable in Settings):** `Space` = pen toggle · `Enter` = activate the focused control; Accept on non-destructive overlays (dictation, AI ghost) · `Esc` = cancel / no · `Backspace` or `Z` = undo · `Y` = redo · `M` = mic on/off (tap; a Settings option makes it hold-to-talk) · `R` = recenter · `P` = pause tracking · `1`–`3` = choose option. Key and voice toggles have no cooldown. One `keydown` listener on `document` that returns early when `event.target` is a button, input, textarea or select, so Space/Enter activate a focused control natively and keys type normally inside the typed-command box, dictation box and profile-name field; Esc returns focus to the canvas. The canvas has `tabIndex=0`; a tile activated by mouse click or dwell calls `canvas.focus()` afterwards (so only Tab navigation leaves focus on a tile; otherwise clicking Latch would make Space re-toggle Latch instead of the pen). A palm or elbow can hit Space and Enter, so any USB/Bluetooth switch that emits Space or Enter works as a one-switch device. README mentions OS Sticky Keys.
- **Face gesture (P3, off until calibrated):** mouth-open is a **tap** (open-and-close, never hold) bound to pen toggle only; thresholds from a per-user calibration ("open your mouth comfortably twice"). Suppressed while the mic is open and for 500 ms after. Eyebrow raise (`browInnerUp`) is the alternative. At startup assert `faceBlendshapes[0].categories` contains `categoryName === "jawOpen"`; if not, log and disable the face toggle.

## 4. Strokes, tools, cleanup
- Record filtered points; render live with `perfect-freehand` (`size` = width, `thinning: 0`, `smoothing: 0.5`, `streamline: 0.4`). On pen-up simplify with RDP ε = 1.5 px and store the stroke as data (points, colour, width, id, timestamp) so undo and SVG export are exact. Multiple named pages, autosaved to `localStorage`.
- Tools (all in the action table): colour `black | white | red | blue | green | yellow | orange | purple`; thick / thin (voice and typed; tile labels "Thicker" / "Thinner"); **straight** (P1: constrains the current/next stroke to a line until "free"); **eraser** (P1: with pen down, passing over a stroke removes it); **zoom in/out/fit, move up/down/left/right** (P3); light/dark canvas background; ruled guide lines on/off. Warn in status when the ink has < 3:1 contrast against the background.
- **Dictation (P2):** "note" / "type" opens a free-text dictation box (a second Ink 2 WebSocket opened without `keyterm` params) that places a text block at the cursor; live transcript shown as a read-only `aria-live` panel while the mic is open (not a focused textarea, so `Enter`/`1`/`Esc` reach the tiles) with Accept (`Enter`), Fix (`1`: reopens the mic and replaces the last sentence) and Cancel (`Esc`) tiles; it becomes an editable textarea only after Accept, and an Edit tile opens it for keyboard users. This is the note-taking half of the product.
- **Local shape cleanup (P2, no network):** closed if end-to-start distance < 15 % of bbox diagonal; line = PCA fit, accept if RMS residual < 3 % of length; circle = Kåsa least-squares, accept if residual/r < 0.08; rectangle/triangle = RDP at 5 % of diagonal, 4 corners at 90° ± 20° (snap axis-aligned within 10°) / 3 corners. "Make this a circle/line/square/triangle" forces the fit on the selected or last stroke.
- **Ask Steady (P3): a cited research assistant for the user's own condition questions.** Voice/typed "ask <question>" (e.g. "why does my hand shake more when I reach?", "what helps thumb pain when writing?"). Pipeline: (1) `scripts/build-index.ts` runs two Apify actors from the AI-agents collection via the Apify REST API (`Authorization: Bearer $APIFY_TOKEN`, `run-sync-get-dataset-items`, `maxTotalChargeUsd` on every call): **`cspnair/rag-knowledge-graph-builder`** over a seed list of ~30 public accessibility/health pages (arthritis.org, essentialtremor.org, parkinson.org, the Procreate accessibility handbook, the One Euro / Camera Mouse / Project Gameface pages, WCAG 2.2) and **`apify/ai-web-scraper`** with the prompt "extract post title, body, date, URL" over 3–5 public forum/community pages about drawing or writing with tremor or arthritis. Read each actor's page on apify.com for exact input fields before calling it; record them in DECISIONS.md. (2) Index the chunks into Elasticsearch Serverless `research` with a `semantic_text` field (Jina embeds automatically) plus `url`, `title`, `source_kind` ('reference' | 'community'), `fetched_at`; fork Elastic's Paper Scout repo (`jdarmada/calhacks-paper-scout`): swap `ingest.py` for this script, keep `setup_agent.py` to create an Agent Builder agent with an index-search tool and one ES|QL tool ("how many community posts mention <term>"), keep `workflows/*.yaml` as a weekly re-crawl workflow that calls the Apify run and re-indexes. (3) `/api/ask` calls the Agent Builder agent (or hybrid search + `claude-haiku-5-5` if Agent Builder is not reachable) and returns an answer with 2–3 citations `[title](url)`; the UI shows it in a panel with **Read it back** (Sonic) and the sources as tiles. Guardrails: answers are general information with a fixed "not medical advice; ask your clinician" line; never personalise from the user's drawings; community posts are labelled as such. **If any of Apify, Elastic or the UI panel is not fully working end to end, delete the whole feature and do not mention Apify or Elastic anywhere.**
- **AI cleanup (Claude, on request only):** "turn my writing into text" (P2), "clean this up" / "label this" (P3) send a PNG crop of the selection plus the stroke list to `/api/cleanup`; the result renders as a ghost overlay with **Accept / Reject** tiles (`Enter` / `Esc`; `Backspace`/`Z` also rejects) before anything is replaced. Log every Claude call to `localStorage` (summary, latency, result, and whether the user Accepted, Rejected, or the timeout fired); the metrics panel shows "Claude: N calls, X accepted, Y rejected, Z timeouts".

## 5. Voice
- **The mic is open only when the user opened it.** Tap `M` or the Mic tile (dwell/click) to open; it closes on the next tap, on 2 s of silence *after the first transcript delta has arrived* (silence before the user starts speaking never closes it; Parkinson's speech initiation can take seconds), or at a cap of 15 s (slider 15–60 s; dictation default 30 s). A canvas dwell does not close it. Live level meter and "Heard: …" status.
- **Cartesia Ink 2 streaming STT**, manual endpoint: `wss://api.cartesia.ai/stt/websocket?model=ink-2&encoding=pcm_s16le&sample_rate=16000&cartesia_version=2026-08-14&access_token=<token>` plus `keyterm=<phrase>` repeated once per voice phrase in the action table (this is what makes commands work in a loud hall). `/api/cartesia-token` mints the token via `POST /access-token` with `grants: { stt: true, tts: true }` (verify the grants schema in the Cartesia access-token reference before writing the route), `expires_in: 3600`; the same token is handed to `@cartesia/cartesia-js` for Sonic; the browser never sees the API key. Capture audio with an `AudioWorkletNode` that downsamples to 16 kHz Int16 and posts 100 ms binary chunks. When the mic closes, send the text message `"finalize"`, then handle `transcript` messages (`text` is a delta; concatenate only chunks with `is_final: true`) until `flush_done`. **Do not use the `/stt/turns/websocket` endpoint or expect `turn.*` events.** Fallback: Web Speech API (Chrome). If both fail, the typed-command box is the offline path. Recommend a headset mic in README.
- **Cartesia Sonic TTS** (via `@cartesia/cartesia-js`) has three jobs: short outcome confirmations you can't see at a glance ("Made it a circle", "Saved page 3", "Didn't catch that; I heard *paint the room*"); **"read it back"**, which reads the recognised text of the current page aloud so a tremor or low-vision user can verify a note; reading clarify options aloud. Togglable.
- **Command resolution, in order:** (1) local grammar over the action table: exact phrase match first, then fuzzy with Levenshtein ≤ 1 for phrases of ≤ 5 characters and ≤ 2 otherwise; a fuzzy tie is no match. No two phrases in `actions.ts` may be within each other's fuzzy threshold: distance ≤ 1 for any pair, and distance ≤ 2 for pairs where both phrases exceed 5 characters (Vitest); short words such as "red"/"pen"/"yes"/"no" may sit exactly 2 apart, the tie rule handles them. Use "redo that", "move up/down/left/right" (not "pan"), and "pen" for the pen toggle (not "pen up"). Fuzzy matching is off while any dialog is open. (2) If no match, POST transcript + context (last 3 actions; selected/last stroke id, type, colour, width; canvas size) to `/api/command`, which calls `claude-haiku-5-5` with `client.messages.parse({ thinking: { type: "disabled" }, output_config: { effort: "low", format: zodOutputFormat(ActionsSchema) }, max_tokens: 1024 })` (`zodOutputFormat` from `@anthropic-ai/sdk/helpers/zod`; Haiku 5.5 thinks by default and thinking counts toward `max_tokens`), SDK `timeout: 2500` (ms), `maxRetries: 0`. Read `response.parsed_output`; it is `null` on parse failure and that is the "Didn't catch that" path. `ActionsSchema` = array of actions from the same enum plus `clarify` with 2–3 options rendered as numbered tiles (`1`–`3`, voice "one/two/three"). Validate with zod; on timeout or invalid output show "Didn't catch that" with the two closest grammar matches as tiles; never discard the transcript silently. `/api/cleanup` uses `claude-sonnet-5-5` with an image block + stroke JSON, `output_config: { effort: "low", format: zodOutputFormat(CleanupSchema) }` for "turn my writing into text" and `effort: "medium"` for "clean this up" / "label this", `max_tokens: 8192`, `timeout: 15_000` (thinking cannot be disabled on Sonnet 5.5 and counts toward `max_tokens`). **Never use forced `tool_choice`** (returns 400 on `claude-sonnet-5-5`); use `parse` + `zodOutputFormat` for both routes.
- **Destructive actions** (clear, delete page, reset calibration, switch profile with unsaved slider changes, Next judge) use the §0 alertdialog (✓ tile, typed "yes", or exact-match voice "yes" confirms; Esc, "no", ✗, or Enter on the focused Cancel cancels), WCAG 3.3.4. Everything else applies immediately and updates the persistent Undo affordance.

## 6a. Desktop mode: draw in Krita and any other app (P2b)
Steady's pipeline drives the real macOS mouse pointer, so the user can paint in **Krita** (the demo app), Figma, Photoshop or any other app without holding a mouse or stylus. Steady's own canvas stays as the place to calibrate, practise and show the Demo panel; Desktop mode reuses the same filtered pointer, dwell, Latch, voice and safety rules.
- **Helper:** `helper/steady_helper.py`, Python 3, using `pynput` (mouse + keyboard control, global key listener) and `websockets`. `helper/requirements.txt`, and `npm run helper` creates a venv, installs the requirements and starts it. It listens on `ws://127.0.0.1:8765` only and **rejects any connection whose `Origin` is not `http://localhost:3000`** (otherwise any website could move the user's mouse). Protocol (JSON, documented in `docs/API.md`): browser → helper `{"t":"move","x":…,"y":…}` (screen points), `{"t":"down"}`, `{"t":"up"}`, `{"t":"click"}`, `{"t":"keys","combo":"cmd+z"}`, `{"t":"ping"}`; helper → browser `{"t":"hello","screen":{"w":…,"h":…}}`, `{"t":"hotkey","id":"pen"|"pause"}`, `{"t":"error","msg":…}`. On macOS, pynput posts drag events while the button is held, which is what Krita needs to paint.
- **Fail safe (the most important rule here):** the helper releases the mouse button (a) if no message arrives for 300 ms (the browser sends `ping` every 100 ms while connected), (b) when the socket closes, (c) on exit, Ctrl-C or any exception. The browser sends `up` on tracking loss (rule 10), on Pause and when Desktop mode is turned off. The button is never left held.
- **Drawing area:** setup asks the user to dwell (or click) on the top-left and bottom-right corners of the Krita canvas; that rectangle is the drawing area (default: the whole main display). The calibrated active box maps onto the drawing area instead of Steady's canvas. **Pen-down (mouse button held) is only possible inside the drawing area.** Outside it, a dwell performs one left click (dwell-click, like Camera Mouse) so the user can pick Krita tools and menus; dwell-click can be turned off. Never drag outside the drawing area.
- **Keeping the browser alive:** Chrome pauses `requestAnimationFrame` and video callbacks in a window that is fully covered. The control window must stay visible: Desktop mode shrinks Steady's UI to a narrow side panel (camera thumbnail with tracking dot, pen state, Mic, Pause, Desktop-mode off, Undo, and the Krita tool tiles) and README tells the user to place Chrome beside Krita, not behind it. `npm run demo-chrome` (a script) launches Chrome at `http://localhost:3000` with `--disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling` as a belt-and-braces fallback. Drive the tracking loop from `requestVideoFrameCallback`, not `requestAnimationFrame`, in this mode.
- **Keys:** while Krita has focus, the browser receives no key events, so the helper owns global hotkeys and relays them as `hotkey` messages: defaults **F8 = pen toggle, F9 = pause tracking and release the button**, remappable in Settings (a USB switch can be programmed to send F8). Never use Space, letters or modifier keys globally (Krita uses them). README notes the Mac `fn` key and that a laptop may need "Use F1, F2 as standard function keys".
- **Voice in Desktop mode:** the same grammar; app-facing actions become keystrokes sent to the focused app through the helper, from a per-app shortcut map in `src/desktop/shortcuts.ts` (Krita on macOS: undo `cmd+z`, redo `cmd+shift+z`, brush `b`, eraser toggle `e`, bigger `]`, smaller `[`, save `cmd+s`). Pen, pause, Latch, steadier/looser and mic stay inside Steady. Canvas-only features (shape fits, AI cleanup, dictation, ghost view) are unavailable in Desktop mode, and the status line says so if asked.
- **macOS permissions (human step):** the helper's terminal app needs **Accessibility** (to move and click the mouse) and **Input Monitoring** (for global hotkeys) in System Settings › Privacy & Security. The helper detects a missing permission at start-up, prints exactly which one to enable, and sends `error` so Steady shows it. Add both to `NEEDS-HUMAN.md`, plus "Install Krita and set its brush smoothing to None (Steady already smooths; double smoothing adds lag)".
- **Tests:** Vitest on the pure mapping (active box → drawing area in screen points; pen-down refused outside the area; dwell inside = pen toggle, outside = click). A Python unit test drives the helper with a fake mouse controller: the button is released after 300 ms of silence, on socket close, and on a bad `Origin`. The real Krita test is a `NEEDS-HUMAN.md` item.

## 7. Demo panel (what judges see; build it in P1)
A collapsible **Demo** panel in the toolbar (`?demo=1` opens it expanded): **Simulate tremor** toggle (adds band-limited 4–10 Hz noise to the **raw landmark pixels before the One Euro filter**, ±4 px at rest rising to ±8 px above 100 px/s, so Steadiness visibly removes it); **ghost view** (raw stroke as a faded ghost under the smoothed stroke); **metrics**: live deviation (RMS px, raw vs smoothed), last-stroke time, command success rate, Claude call counts, camera/detection fps; a **Next judge** tile (visible only with `?demo=1`, marked destructive: clears canvas, resets metrics, restarts the 10 s calibration). The first demo screen shows one sentence from the user interview (`docs/user-interview.md`). Metric formulas are in README so they read as evidence.

## 8. Edge cases
**Must handle in code (test or explicit UI):** tracking lost mid-stroke (in Desktop mode: mouse button released); helper not running or permission missing (Desktop mode tile shows why and how to fix it); Chrome window covered by Krita; dim light / low detection fps warning; desk-level hand not visible to a laptop webcam (calibration coaching, in order of preference: external webcam or phone-as-webcam on a stand looking down at the desk; laptop pushed back with the lid tilted ~30° down; Head mode; never a vertical forearm steered by the wrist); dwell firing during slow deliberate drawing (pen-up rule, Latch); blobs at stroke ends; network down (grammar + typed box still work; voice and AI cleanup disabled with a clear message); Claude timeout / invalid output; accidental clear (confirm + undo); page reload (autosave); non-Chrome browser (banner: "use desktop Chrome").
**Document in README › Limitations:** wheelchair/bed camera angles; glasses; lower detection confidence for darker skin tones in low light (surface confidence and the lighting fix); dysarthric and accented speech (accuracy not measured); non-English; multiple tabs; neck fatigue in Head mode; two hands in frame.
