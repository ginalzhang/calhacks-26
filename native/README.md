# Steady native phase-01 probe

This Swift 6.4 package targets arm64 macOS 26.0 with the installed macOS 27.0 SDK. Electron owns and launches the executable from its packaged resources outside ASAR. It is not a separately launched service. It requires no compiler, interpreter, checkout, TCP port, or native resource directory at runtime.

Use the root `npm run build:native` and `npm run test:native` scripts. The former copies the release executable to `resources/bin/SteadyNative`. The pinned Command Line Tools currently require explicit loading of their installed Swift Testing macro plugin; the root test script records that path. SwiftPM's default build backend can compile/run Swift Testing, while its native backend builds the release executable without the sandbox-restricted dSYM operation. These are SwiftPM build backend flags, not a version or stack change.

`native/Tests/integration.py resources/bin/SteadyNative` runs seven process checks using `--test-fake-backend`: real stdio framing, eight-round-trip clock mapping, live-heartbeat starvation release, EOF while a fake button is held, default/emergency fake release, oversized-frame rejection, exact bounded-probe EOF release idle speech counters, and deferred-voice rejection before permission/asset/capture work. Python is a development test harness only. No automated check accesses cameras/microphones, observes real desktop activation or injects desktop events.

## Runtime arguments

- No arguments: real permission, foreground and display diagnostics, fake event posting. Microphone stays off and no speech assets install automatically.
- `--test-fake-backend`: deterministic synthetic display/permissions/foreground and observable fake event diagnostics on stderr. Cannot be combined with real input.
- `--release-and-exit`: unconditional mouse-up attempt through the selected backend; default backend posts nothing. Electron passes `--real-input` when releasing after a real helper. This emergency path works before the normal packaged-identity restriction.
- `--real-input`: opt into Quartz posting. Normal real operation requires the executable to be inside `Steady.app/Contents/`; target bundle/PID and Accessibility are checked immediately before input down/move/shortcut posting. Mouse-up always attempts release.
- `--probe --real-input`: Electron-owned supervised probe. The UI must explain the operator must open a disposable Krita canvas, position the physical pointer with at least 12 logical points of clear canvas to the right, and keep Krita foreground. Electron writes `CONFIRM_DISPOSABLE_KRITA\n` after explicit operator confirmation and a switching delay. Confirmation expires after 15 seconds. The probe uses the current pointer, posts no more than a 10-point rightward stroke, tests starvation, attempts release, and exits in approximately 1.2 seconds after confirmation. It has its own independent 10 ms watchdog. Optional `--probe-rect x y width height` supplies an operator-confirmed logical Quartz canvas; otherwise a 100x100 probe rectangle around the current pointer must fit the primary display. This does not calibrate the application or validate later product drawing behavior.

## Protocol and safety

The compatibility contract is `src/shared/contracts.ts` and `fixtures/protocol-v1.json`. UTF-8 newline JSON is bounded to 16 KiB excluding newline. All timestamps are monotonic milliseconds; renderer/main clocks must be converted to native before capture submission. Hello returns protocol version, actual permission states, authoritative Quartz displays and capabilities. Native requests/replies have independent increasing safe-integer sequence numbers in one UUID session. Unexpected versions/types/actions, malformed frames, changed sessions and invalid payloads fault; expired generations, old frames and repeated commands are rejected.

The native engine launches paused and pen-up. Nonnull configured canvas is parent confirmation, not proof of calibration. Parent must gate calibration/canvas prerequisites; phase-01 main intentionally blocks normal drawing. 500 ms valid tracking is required for Resume. A capture age of 250 ms pauses/releases, checked every 10 ms independently of speech and parsing. Pings never refresh capture freshness. Foreground/PID/permission loss, display changes, EOF, signals and explicit emergency release all attempt mouse-up. EOF monitoring does not depend on stdout draining. Output sequence allocation and writing share a gate; engine locks are released before pipe writes. The watchdog sends diagnostics on a separate queue so pipe backpressure cannot stall release.

Platform metadata is collected outside the input lock on its own queue; the freshness timer, state snapshot and clock ping use the latest authoritative native snapshot. Action/configuration requests refresh metadata before taking the input lock. Native workspace activation pauses/releases directly; Quartz reconfiguration invalidates/releases before refreshing geometry. Real event posting still checks current Accessibility, foreground bundle and PID immediately before posting, and a rejected post pauses/releases without claiming a held button. Emergency release posts before metadata/engine initialization. Clock synchronization remains exactly eight round trips with a10ms uncertainty gate; readiness is reported separately from the first hello state.

## Speech probe and limits

**Superseding user amendment,2026-10-24:** voice is deferred to Phase 04. The helper rejects microphone enable and speech-asset installation with `voice-deferred-phase01`; disable remains allowed. Speech recognition/diagnostic code and the historical findings below are preserved, but microphone capture cannot start through this Phase 01 protocol. The downloaded `ThirdParty/libfvad/` sources are an inactive interrupted import: Package.swift has no C target or dependency, and the VAD is neither compiled nor shipped as an active runtime dependency. [Scope and authorization](../plan/ledger/phase-01-20261024-01/artifacts/voice-deferral-01.md).

**Mandatory feasibility blocker, independently verified during review:** Apple's [SpeechDetector results documentation](https://developer.apple.com/documentation/speech/speechdetector/results) states that the result sequence otherwise remains empty; [Result documentation](https://developer.apple.com/documentation/speech/speechdetector/result) currently describes VAD error handling only. SDK27 exposes the types but does not prove speech boundary events. The required detector-based400ms utterance endpoint and speech-end-to-action timings cannot be claimed from compilation or final transcription callbacks. No custom VAD, alternate recognizer or fabricated timestamp substitutes for the fixed plan. Phase01 remains blocked pending authoritative/runtime evidence resolving this assumption or an explicitly approved plan revision.

Only `installSpeechAssets` requests Apple-managed `en-US` asset installation. Only explicit `microphone.enabled` requests microphone/speech permission and starts capture. Uses `SpeechAnalyzer`, `SpeechTranscriber` with `fastResults`/`audioTimeRange`, and `SpeechDetector`. Converts capture buffers into an analyzer-compatible format, keeps bounded audio buffering, and fails closed on overrun, conversion errors or missing host timestamps. It never falls back to a cloud recognizer.

Utterances end after 400 ms detected silence or a six-second limit. `finalize(through:)` requests finalization to the silence boundary; only finalized spans are assembled. The consumer requires its finalization watermark before accepting. Missing finalization evidence expires with a visible retry event. Results older than 1.5 seconds, inactive/replaced sessions, tentative spans, unknown/unprefixed/multiple commands never act. Each accepted utterance emits recognition-only `speech`; Electron dispatches it once and must use the eventual native action ack to measure speech-end-to-action latency.

Speech end maps audio sample time to the input tap's valid host timestamp and the native monotonic clock, never to the final callback. Detector boundary accuracy, audio conversion/device timing, behavior of finalization watermarks, actual offline recognition, and the ten-probe nearest-rank p95 remain **not run / mandatory hardware blockers**. No transcripts or recordings are persisted. Compiling SDK calls and passing synthetic assembly tests do not prove live speech behavior.

The user-authorized feasibility continuation adds `steady-speech-probe:` JSON counters on stderr at most once per second: phase/assets, audio buffers/seconds, transcriber results/finals, detector speech/silence results and accepted utterances. Counters contain no recognized text/audio. Activation tokens invalidate old audio/result callbacks, and stopped snapshots retain final counts. Electron accepts only the bounded allowlisted schema for the current speech session and exposes it in Settings. Numeric evidence is stored in userData `phase01-evidence/speech-diagnostics.jsonl`, capped at1MiB with unchanged snapshots suppressed. `trialSession` associates the final stopped snapshot with its microphone trial. Diagnostic observation timestamps are not speech-end timestamps and cannot replace the fixed voice timing measurement.
